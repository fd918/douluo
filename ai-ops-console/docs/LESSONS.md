# 可复用开发经验

## AI 网关的“调用次数”与“额度消耗”必须分开

一次玩家请求可能因主服务失败产生多次上游尝试。运营看板可以统计上游尝试数，但限流额度必须按逻辑请求计数，否则备用降级会错误扣除多次额度。

## 服务商密钥与主密钥必须成对备份

SQLite 中保存加密后的服务商密钥，本地 `master.key` 用于解密。迁移时只复制数据库会导致密钥无法恢复，因此两者必须作为一个备份单元。

## 管理界面与公网运行层必须解耦

本机页面只负责发出受保护的配置命令，公网 Worker 从 D1 读取最后保存的配置。这样关机只会暂时失去管理入口，不会让玩家的 AI 请求依赖某台个人电脑在线。

## 金额必须由输入与输出 Token 分开计算

不同模型通常分别计价输入和输出。价格统一保存为“人民币 / 100 万 Token”，金额使用整数微元存储，展示时再换算，避免浮点累计误差。
