# 可复用开发经验

## 原型外框与真机运行必须分开

设备外框、模拟状态栏和键盘只适合电脑演示。真手机应使用 `100dvh`、`viewport-fit=cover`、系统安全区和原生键盘；发布前必须使用 390×844 等真机视口自动检查外框、选择器和横向溢出。

## 短地址与密钥安全可以分层解决

GitHub Pages 适合提供简短稳定的静态游戏地址，但不能保存 AI 密钥。前端使用子路径基地址构建，再通过限定来源 CORS 调用独立 Worker，可以同时获得短地址与服务端密钥保护。

当测试阶段明确选择“玩家自带密钥”时，GitHub Pages 也可以直连支持浏览器 CORS 的 OpenAI 兼容服务。前提是代码不预置真实密钥、配置只存当前浏览器、连接测试成功后才启用，并且任何网络或格式错误都立即回到完整的本地规则玩法；这一路径不具备服务端 D1 限流和运营统计能力。

## AI 生成世界变化必须通过规则层

AI 只负责提出事件文本和受限变化；服务端先按请求白名单清理 ID，客户端再按数值上限、存档字段和内容目录校验。这样即使模型输出越界，也不会直接赠送神器、跳过主线或破坏存档。

部分 OpenAI 兼容供应商会忽略 `enable_thinking: false`，并把内部推理计入 `max_tokens`。结构化输出不能只按最终可见文字估算额度；应为低频复杂 JSON 预留推理空间，再由规则层裁剪最终字段长度。

## 公开限流需要持久化且隐私最小化

公开 Worker 的分钟/每日预算使用 D1 原子 UPSERT，避免多实例内存计数不一致；只保存加盐 SHA-256 来源摘要，不保存原始 IP。D1 故障时回退内存，保证游戏仍可用。

## 扩展内容采用纯数据和声明式解锁

武魂、势力、人物、地点、魂兽与随机事件保持为纯数据，统一通过 `WorldProgress` 查询解锁。界面与存档只消费查询结果，后续扩内容时无需复制业务判断。

## H5 音频解锁必须合并并发请求

首次触摸自动解锁与声音按钮点击可能落在同一交互周期。控制器应复用同一个解锁 Promise，并且只在解锁成功后切换静音状态，避免后一条流程暂停前一条刚恢复的音轨。

## 原始美术与手机运行资源分层保存

高分辨率 PNG 适合作为源资产，不适合直接进入手机首屏。为实际显示尺寸生成 WebP 衍生图，声明宽高并按需加载非首屏图片，可以在不损失源文件的前提下显著降低 H5 首次下载量。

## 主线叙事与开放世界操作必须分层

旅行、随机支线和物品操作可以记录到时间线，但不应改写当前主线节点和主线旁白。主线只在剧情选择与明确的剧情回应中推进，才能避免页面标题、旁白和任务目标彼此跳脱。

## H5 系统语音不能作为微信旁白的唯一通道

安卓 Chrome、厂商浏览器和微信 WebView 对 `speechSynthesis` 的实现并不一致。固定剧情应随包提供按需加载的普通网页音频，系统语音只承担无法预生成的动态文字；首个用户点击同时用于解锁音频，自动播放被拦截时在下一次触控中重试。

## 国内 H5 首屏不能依赖境外字体样式

远程字体的 CSS 本身可能包含大量中文字符分片声明，并成为渲染阻塞资源。在微信和国内移动网络中应优先使用系统中文字体；首屏确定使用的小尺寸场景图可以预加载，其余图片继续按需加载。

## 沉浸旁白必须同时设计人声、音乐与空间

只把系统 TTS 导出为低码率 MP3，会保留机械语速、干薄频响和逐字播报感。固定剧情应使用适合小说的神经网络音色、自然短句、段落留白和轻人声母带。主旁白保持稳定，第二音色只承担明确的“命运之声”角色，避免随机换声破坏叙事身份。

旁白 MP3 不应内置 BGM。游戏保持唯一、连续且可独立控制的场景音乐，在旁白出现时柔和压低，结束后恢复；这样不会出现两套音乐叠加、每段旁白重启音乐或用户关闭音乐却仍能听到内嵌伴奏的问题。

多个 `HTMLAudioElement` 首次解锁时不应都指向真实 BGM，否则手机会产生重复 Range 请求。用极短的内嵌静音 WAV 完成用户手势解锁，再只给实际播放通道设置当前场景音轨，可以避免无意义的首轮音乐下载。
