# 可复用开发经验

## 原型外框与真机运行必须分开

设备外框、模拟状态栏和键盘只适合电脑演示。真手机应使用 `100dvh`、`viewport-fit=cover`、系统安全区和原生键盘；发布前必须使用 390×844 等真机视口自动检查外框、选择器和横向溢出。

## 短地址与密钥安全可以分层解决

GitHub Pages 适合提供简短稳定的静态游戏地址，但不能保存 AI 密钥。前端使用子路径基地址构建，再通过限定来源 CORS 调用独立 Worker，可以同时获得短地址与服务端密钥保护。

## AI 生成世界变化必须通过规则层

AI 只负责提出事件文本和受限变化；服务端先按请求白名单清理 ID，客户端再按数值上限、存档字段和内容目录校验。这样即使模型输出越界，也不会直接赠送神器、跳过主线或破坏存档。

部分 OpenAI 兼容供应商会忽略 `enable_thinking: false`，并把内部推理计入 `max_tokens`。结构化输出不能只按最终可见文字估算额度；应为低频复杂 JSON 预留推理空间，再由规则层裁剪最终字段长度。

## 公开限流需要持久化且隐私最小化

公开 Worker 的分钟/每日预算使用 D1 原子 UPSERT，避免多实例内存计数不一致；只保存加盐 SHA-256 来源摘要，不保存原始 IP。D1 故障时回退内存，保证游戏仍可用。

## 扩展内容采用纯数据和声明式解锁

武魂、势力、人物、地点、魂兽与随机事件保持为纯数据，统一通过 `WorldProgress` 查询解锁。界面与存档只消费查询结果，后续扩内容时无需复制业务判断。

## H5 音频解锁必须合并并发请求

首次触摸自动解锁与声音按钮点击可能落在同一交互周期。控制器应复用同一个解锁 Promise，并且只在解锁成功后切换静音状态，避免后一条流程暂停前一条刚恢复的音轨。

## 原始美术与手机运行资源分层保存

高分辨率 PNG 适合作为源资产，不适合直接进入手机首屏。为实际显示尺寸生成 WebP 衍生图，声明宽高并按需加载非首屏图片，可以在不损失源文件的前提下显著降低 H5 首次下载量。

## 主线叙事与开放世界操作必须分层

旅行、随机支线和物品操作可以记录到时间线，但不应改写当前主线节点和主线旁白。主线只在剧情选择与明确的剧情回应中推进，才能避免页面标题、旁白和任务目标彼此跳脱。
